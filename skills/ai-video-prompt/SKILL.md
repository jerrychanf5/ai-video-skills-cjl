# AI 视频提示词生成与优化（Skill B）

> 定位：把已有的画面意图转译为可直接粘贴使用的视频生成提示词，或对已有提示词做质量优化。
> 工具适配：以 LibTV（可灵/即梦系）为基础；其他工具差异以括号备注。
> 知识源：`../../产物/5-AI视频创作通用手册-第二版.md` + `../../产物/6-影视飓风AI提示词-AI学习版.md`
> 案例库：预留接口（阶段 2 接入极空间 MCP，当前跳过）

---

## 三种入口（先判断用户是哪种）

| 入口 | 特征 | 处理路线 |
|---|---|---|
| **A：有构思单/分镜** | 用户提供了结构化分镜描述或《内容构思单》 | 直接进入逐镜转写 |
| **B：口头描述想法** | 用户用自然语言说"我想拍一个……" | 先梳理成逐镜结构，确认后转写 |
| **C：优化已有提示词** | 用户粘贴了已有提示词，要改得更好 | 进入优化检查模式 |

入口 B 需要追问的最少信息：画面里有没有人物、大概时长、有没有底图。其他缺项先输出，末尾标注假设。

## 生成路线（入口 A / B）

### 第 1 步：逐镜判型

| 镜头类型 | 判断条件 |
|---|---|
| 图生视频·纯场景 | 有底图，无人物出镜 |
| 图生视频·数字人 | 有底图，有数字人口播 |
| 首尾帧 | 两张图做动态过渡或循环 |
| 文生视频 | 无底图，纯文字生成 |

⚠️ **边界案例**：需要背景路人（增加生活气）但非口播数字人 → 负向词不能写"出现任何人物"，改为约束行为（不聚焦面部/不直视镜头）。

### 第 2 步：逐镜转写

**图生视频基础结构**：
```
【场景】[一句话：场景主体 + 光线氛围]
输入图片作为静态背景层。严禁修改图中任何元素，不得添加、删除、移动图中任何物体，不得出现图片之外的任何场景或物品。
微动态：[只写图中已有元素的自然动态，如水流、树叶、光斑]
音效：[音源 + 行为 + 环境]

【运镜】[一种运镜：方向 + 速度]

【口播】（如有）"……"

【时长】Xs

【负向提示词】[5-8 个]
```

**四条转写规则**：
1. 静态归图片，动态归提示词——不重复描述图中已有内容
2. 一个镜头只写一种运镜，与主体动作分开写
3. 速度默认"缓慢/匀速"，不写"快速"（必然运动模糊）
4. 数字人段：形象锁 + 光影匹配 + 动作按时间节拍 + 口型收敛句

### 第 3 步：时长核算（有口播的镜头必做）

- 1.3 倍语速 ≈ 5.4 字/秒
- 段时长 = 动作引入（1-2s）+ 口播需时 + 收束（0.5-1s）
- 口播装不下时，告知用户三选一：**加时长 > 删动作不删字 > 边走边说（风险略高）**

### 第 4 步：全片自检

- [ ] 全片运镜是否过于集中于"推"系？
- [ ] 场景句有没有重复描述图中静态内容？
- [ ] 具体数字（价格/面积）是否全部未入提示词？
- [ ] 每段有无收束动作（0.5-1s）？

### 第 5 步：输出格式

片头信息（批次/类型/段数）→ 时长核算表（口播段）→ 逐段提示词 → 制作流程备注。

## 优化路线（入口 C）

用户粘贴已有提示词时，执行以下五项检查并给出修改建议：

| 检查项 | 说明 | 修法 |
|---|---|---|
| **Vanity Zoom** | 细节描述过密 → 模型自动拉近失控 | 精简描述，专注运动 |
| **Missing Legs** | 全身构图容易切腰 | 加"含脚部到画面底部"约束 |
| **负向词摆放** | 可灵：独立负向栏可写完整清单；其他平台：写进正文紧贴被保护元素；Sora/Runway：无负向机制，全转正向描述 | 按工具区分 |
| **公式冲突** | 图生视频却写了大量静态画面描述 | 删静态，只留动态+运镜 |
| **运镜冲突** | 同一镜头写了两种运镜 | 拆成两段分别生成 |

输出：逐条问题说明 + 修改后版本。

---

## 硬停止

- 用户只说"想做一个视频"但没有任何画面意图 → 告知转用 `ai-video-creative` 先做创意发散
- 用户提出合规风险内容（真人肖像无授权/虚假数据宣传）→ 停止并说明

---

## 红线

- 不改变用户的画面意图：发现构思单有矛盾 → 停下报告，不自行取舍
- 不写具体数字（价格/面积/分钟数）→ 一律"字幕层处理"
- 未授权素材标注"⚠️ 待授权确认"（真人肖像/品牌 Logo）
- 不替用户决策：多个方案时给选项，用户选
